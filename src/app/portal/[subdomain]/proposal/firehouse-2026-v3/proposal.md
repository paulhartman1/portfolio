## Executive Summary

Firehouse will retain WordPress as its content management system. CGT will modernize the public website within WordPress to improve maintainability, navigation, performance, accessibility practices, and the staff editing experience while preserving existing operational systems where they continue to serve Firehouse effectively.

This project is not a custom replacement for WordPress, and it is more than a cosmetic theme change. CGT's review of the current site found that the visible problems are tied not only to the active theme, but also to years of accumulated page-builder markup, content history, plugins, duplicated structures, and external service integrations.

The recommended approach is therefore a bounded WordPress modernization: keep the platform Firehouse already knows, preserve effective existing systems, and replace or simplify the presentation and editing structures that make the current site difficult to maintain.

---

## What CGT Found

Before recommending this approach, CGT reviewed the current WordPress environment, including the active theme and child theme, plugin inventory, editing environment, page structure, representative legacy content, and existing external systems.

Key findings include:

- The active site uses the **Beyond Child** theme on the **Beyond** parent theme.
- Legacy editing relies heavily on **Classic Editor**, **WPBakery / Visual Composer shortcodes**, inline styling, and raw HTML.
- The site contains **93 observed WordPress pages**, including current content, historical material, drafts, overlapping concepts, and obsolete content.
- Representative pages show that content and presentation are often stored together, making updates harder than they need to be.
- Some recurring pages contain current and historical material in the same page rather than maintaining clean current/archive boundaries.
- Event-related WordPress infrastructure exists, but no active event records were observed during review; Firehouse's actual workflow continues to rely on **Google Calendar** and external services.
- Existing tools already handle important operational functions such as registrations, payments, forms, auctions, newsletters, and ecommerce.

The research supports staying on WordPress. It does **not** support treating the project as a simple theme installation.

---

## Problems Behind the Findings

The findings above point to practical operating problems that affect both staff and visitors:

- Legacy page-builder markup and mixed editing patterns increase update time and make routine changes harder for staff.
- Content and presentation are often coupled, so small edits can create layout inconsistency or unintended formatting issues.
- Historical and current material coexisting in the same page increases risk of stale, conflicting, or unclear public information.
- Layered theme/plugin dependencies increase long-term maintenance complexity and raise the likelihood of regressions during updates.
- Fragmented external workflows can create disjointed visitor journeys when presentation and navigation are not intentionally coordinated.
- Rebuilding all historical content one-for-one is not cost-effective for this engagement and does not target the highest-value outcomes.

This is why the proposal is structured as a bounded modernization: preserve what works, reduce maintenance burden, and improve public experience without unnecessary system replacement.

---
## Practical Diagnosis

The maintainability problem is primarily accumulated structure and editing debt, not WordPress itself.

A cosmetic theme change alone would leave much of the existing content and editing structure intact.

The recommended path is a bounded WordPress modernization that preserves Firehouse's familiar CMS and effective operational systems while improving consistency, structure, presentation, and editing clarity.

## Scope Boundaries & Assumptions

**WordPress remains.** The board's decision to stay on WordPress is respected; this project will not replace WordPress.

**Migration is bounded.** The project includes priority launch content representing approximately 25 standard existing pages, not wholesale reconstruction of the full historical site.

**Integrations are bounded.** Existing tools may be connected using links, embeds, configuration, or existing supported plugins. Custom API work is excluded unless separately scoped.

**Artist/member work is public presentation only.** No custom membership CRM, billing, approvals, or administrative workflow system is included.

**Accessibility work is implementation-focused.** WCAG-informed practices are applied to the rebuilt site; no legal compliance certification is provided.

**Testing is representative and scope-specific.** CGT will validate the parts of the site affected by this project. Comprehensive testing of unrelated third-party systems is not included.

**Client responsibilities.** Firehouse will provide timely access, review, approvals, plugin/license information where needed, and content decisions required to keep the project moving.

## Why This Recommendation Changed

The earlier platform proposal responded to a broader set of requested capabilities and assumed that a new administrative system would be needed to support them.

The board has now clarified that retaining WordPress is itself an important organizational requirement.

CGT reviewed the existing WordPress implementation against that requirement and found that the core website problems can be meaningfully addressed without replacing the platform.

The recommendation changed because the understanding of the problem changed.

The current recommendation is therefore to modernize WordPress rather than replace it.

This section summarizes direct observations from CGT's preliminary WordPress review and explains the basis for the modernization recommendation.

- The active site uses the **Beyond Child** theme on the **Beyond** parent theme.

- **93 WordPress pages** were observed during the preliminary inventory.
- The inventory includes current pages, drafts, historical campaigns, overlapping concepts, and obsolete material.
- Representative legacy pages mix content, layout, historical information, and third-party links inside manually assembled page content.
- Repeated and overlapping pages indicate a need for intentional migration and clearer information architecture rather than one-for-one reproduction.

- Event plugin infrastructure exists in WordPress, but no active event records were observed during review.
- Firehouse's actual operational workflow continues to rely on external systems such as **Google Calendar** and other service platforms.
- The modernization should preserve effective systems of record rather than duplicate them unnecessarily.
