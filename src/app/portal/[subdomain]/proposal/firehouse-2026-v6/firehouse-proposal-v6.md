## The Project

Firehouse Art Center has decided to retain WordPress and replace its current theme with a more modern foundation.

Common Ground Technology will implement that change while protecting the existing website, resolving the specific technical issues identified for this project, and improving the parts of the site most important to Firehouse staff and visitors.

This is intentionally a bounded project.

It is **not** a replacement for WordPress, and it is **not** a rebuild of the custom platform previously explored.

It is also more than installing a theme and changing colors.

CGT's preliminary review found that much of the current site's layout is stored in legacy WPBakery page-builder content rather than in the theme itself. Changing the theme can therefore affect the visual frame of the site — navigation, typography, header, footer, colors, spacing, and related presentation — without automatically redesigning the content inside every existing page.

This proposal accounts for that distinction.

---

## What CGT Found

CGT reviewed the current WordPress environment before quoting — theme and child theme, plugins, editing stack, page inventory, and the external systems Firehouse uses. That review is included whether or not Firehouse proceeds.

**The theme is customized.** The site runs Beyond Child on the Beyond parent theme, so a theme change has to be tested on a copy of the site before it goes near the live one.

**The site depends on WPBakery Page Builder.** It appears to be included with the current theme rather than licensed to Firehouse directly, and the installed version is 7.8 against a current release of 9.0. This is the central technical risk in the project. See below.

**There are 93 pages, 77 of them published**, spanning roughly a decade, with several duplicated concepts.

**The events plugins hold no records.** The Events Calendar and Event Tickets are installed and active but empty. Firehouse's events live in Google Calendar, and CGT does not recommend investing in the unused WordPress event system.

**Nothing indicates the site is broken or unsafe.** Outdated software and lapsed licenses are maintenance items, noted because they affect planning.

**On the plugin problem:** Firehouse's understanding is that the current theme won't accept certain plugins. Themes don't generally block plugins. The likely causes are the PHP version, a conflict with the current editor configuration, or the outdated page builder. The specific issues Firehouse identified as motivating the theme change will be investigated and resolved as part of this project.

## Protecting the Existing Site

Because WPBakery appears to be tied to the current theme, changing the theme carries real risk: if the page builder becomes unavailable, pages built with it can stop displaying correctly.

CGT will purchase an independent WPBakery license for Firehouse, install it before any theme work begins, and confirm on a staging copy that pages still render. **The license cost is included in the fee.** After this, the page builder belongs to Firehouse rather than to the theme.

All work happens on a staging copy. The live site is backed up first and is not touched until Firehouse approves the launch.

## Scope of Work

### 1. Setup and Safety
- Staging copy of the live site
- Full backup before any change
- Independent WPBakery license purchased and installed
- Confirmation that existing pages render correctly before proceeding

### 2. Diagnosis and Issue Resolution
- Identification of the actual cause of the reported plugin problems
- PHP and platform configuration corrected as needed
- Theme and page builder brought up to date
- The specific issues Firehouse identified as motivating the theme change will be investigated and resolved
- These will be listed in Appendix A and confirmed before work begins

### 3. Theme Selection
- Two or three modern, actively maintained theme options presented, with a recommendation
- Themes chosen for compatibility with the existing site rather than for demo appearance
- Firehouse approves the selection before configuration begins

### 4. Theme Configuration
- Installation and configuration on staging
- Header, primary navigation, and mobile navigation
- Footer
- Firehouse logo, brand colors, and typography applied site-wide
- Review of existing child-theme customizations so current functionality is preserved

### 5. Page Verification and Correction
Every published page is reviewed under the new theme and corrected where the transition has affected it — spacing, column alignment, button styling, image sizing, and similar.

The **10 highest-traffic pages**, selected with Firehouse from analytics, receive closer attention and are brought to a properly finished state.

Remaining pages are brought to a correct and consistent state, not redesigned.

### 6. Mobile, Accessibility, and Performance
- Responsive behavior checked at representative phone, tablet, and desktop sizes
- Heading structure, keyboard navigation, color contrast, and image alt text addressed on the theme and priority pages
- Image optimization and reduction of unnecessary front-end weight where practical

WCAG 2.2 Level AA is a working target for implementation practice, not a legal compliance certification.

### 7. Testing and Launch
- Current browsers and common phone sizes
- Existing forms, donation links, and shop functionality verified working
- Existing web addresses preserved so search rankings and external links are not lost
- Redirects for any address that intentionally changes
- Launch coordinated at a time Firehouse chooses

### 8. Training and Handoff
- One 90-minute staff training session, recorded
- Written reference notes for common editing tasks

## Scope Boundaries

**WordPress remains.** This project does not replace WordPress.

**Page layouts are not rebuilt.** Pages are corrected and made consistent under the new theme, not redesigned. See "What a New Theme Changes."

**WPBakery remains in place.** Legacy page-builder markup is retained, now under a license belonging to Firehouse.

**Existing systems are preserved.** Sawyer, PayPal, Square, Google Calendar, Google Forms, WooCommerce, Mailchimp and other current tools continue to operate as they do today. No custom integration work is included.

**No new systems.** No new events, membership, or e-commerce functionality is built.

**Firehouse provides:** WordPress and hosting administrator access, Google Analytics access, logo and brand files, the list of specific issues to resolve, a single named decision-maker, and feedback within 5 business days at each review point.

**Hosting access assumption:** This proposal assumes CGT can obtain the hosting, server, database, and related access necessary to safely back up, stage, test, and deploy the existing WordPress site. CGT has previously requested this access, but it has not yet been established. If recovering or replacing the existing hosting infrastructure requires additional investigation, vendor coordination, account recovery, migration, or infrastructure setup, that work is outside this proposal and will be scoped separately before proceeding.

## Why the Recommendation Changed

The earlier proposal responded to a broad set of requested capabilities and assumed a new administrative system would be needed to support them.

The board has since made clear that staying on WordPress, and keeping staff able to update the site directly, is itself a requirement. CGT reviewed the existing installation against that requirement and found it can be met.

The recommendation changed because the understanding of the requirement changed.
